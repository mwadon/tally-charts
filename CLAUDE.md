## Konwencje
- Każda nowa funkcja ma testy.
- Bez sekretów w repo; konfiguracja przez zmienne środowiskowe (.env.example).
- Commity i gałęzie robi orkiestrator, nie agent.
- Każdy PR zmieniający `packages/tally-charts` ma changeset (`pnpm changeset`, katalog `.changeset`).
- Zmiana łamiąca publiczne API ma changeset `major` z notatką migracyjną: fragment kodu „przed” i „po”.
- Baseline'y wizualne są per platforma w `apps/storybook/e2e/__screenshots__/{darwin,linux}`. Darwin: `pnpm --filter storybook-app exec playwright test --update-snapshots=all`. Linux wyłącznie komendą docker z komentarza nad jobem `e2e` w `.github/workflows/ci.yml` (nie kopiuj jej tutaj). CI nigdy nie zapisuje baseline'ów.
- Baseline'y strony głównej docs (`apps/docs/e2e/home-visual.spec.ts`, 1280/375 × light/dark) są w `apps/docs/e2e/__screenshots__/{darwin,linux}`. Darwin: po `pnpm build && pnpm --filter docs build`, przy wolnym porcie 3100, `pnpm --filter docs exec playwright test --update-snapshots=all`. Linux wyłącznie komendą docker z komentarza nad jobem `docs` w `.github/workflows/ci.yml` (nie kopiuj jej tutaj). Zmiana wyglądu `/` wymaga odświeżenia obu platform. Strona `/docs/line-chart` ma osobne baseline'y (`apps/docs/e2e/line-chart-visual.spec.ts`, `line-chart-1280-{light,dark}.png`, 1280×1400, oba wykresy przewinięte przed zrzutem, te same katalogi `{darwin,linux}`); komenda docker z komentarza nad jobem `docs` odświeża oba speki wizualne (home-visual i line-chart-visual), a zmiana wyglądu `/docs/line-chart` wymaga odświeżenia obu platform (darwin: dopisz `e2e/line-chart-visual.spec.ts` do komendy playwright).
